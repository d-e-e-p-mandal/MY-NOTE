🔹 1. Change Tracking 🔥

⸻

🧠 Definition

👉 Change Tracking means:

EF Core automatically tracks changes made to entities

⸻

📌 Example

var emp = db.Employees.Find(1);

emp.Name = "Updated";

db.SaveChanges();


⸻

🧠 What happens internally?
	1.	EF loads entity → State = Unchanged
	2.	You modify → State = Modified
	3.	SaveChanges() → UPDATE query

⸻

🔥 Entity States

State	Meaning
Added	New entity
Modified	Changed entity
Deleted	Removed
Unchanged	No change
Detached	Not tracked


⸻

⚡ Why important?
	•	No need to write update queries
	•	EF handles everything automatically

⸻

🔹 2. Tracking vs No Tracking 🔥

⸻

🧠 Tracking (Default)

👉 EF tracks changes

var emp = db.Employees.ToList();


⸻

✅ Advantage
	•	Can update data easily

❌ Disadvantage
	•	More memory usage
	•	Slower for read-only

⸻

🧠 No Tracking

👉 EF does NOT track changes

var emp = db.Employees
            .AsNoTracking()
            .ToList();


⸻

✅ Advantage
	•	Faster
	•	Less memory

❌ Disadvantage
	•	Cannot update directly

⸻

🎯 When to use?

Scenario	Use
Read-only data	No Tracking ✅
Update data	Tracking ✅


⸻

🔹 3. Transactions 🔥

⸻

🧠 Definition

👉 Transaction ensures:

All operations succeed OR all fail

⸻

📌 Example

using var transaction = db.Database.BeginTransaction();

try
{
    db.Employees.Add(emp1);
    db.Employees.Add(emp2);

    db.SaveChanges();

    transaction.Commit();
}
catch
{
    transaction.Rollback();
}


⸻

🧠 Why needed?

👉 Example:
	•	Transfer money
	•	Insert multiple records

👉 If one fails → rollback all

⸻

🔥 Key Points
	•	Commit() → Save
	•	Rollback() → Undo

⸻

🔹 4. Raw SQL Queries 🔥

⸻

🧠 Definition

👉 Run direct SQL inside EF Core

⸻

📌 Example (SELECT)

var data = db.Employees
             .FromSqlRaw("SELECT * FROM Employees")
             .ToList();


⸻

📌 Example (Parameterized)

var data = db.Employees
             .FromSqlRaw("SELECT * FROM Employees WHERE Id = {0}", 1)
             .ToList();


⸻

📌 Execute Non-Query

db.Database.ExecuteSqlRaw("DELETE FROM Employees WHERE Id = 1");


⸻

⚡ Why use Raw SQL?
	•	Complex queries
	•	Performance optimization
	•	Stored procedures

⸻

🔹 5. Stored Procedures 🔥

⸻

🧠 Definition

👉 Stored Procedure = Predefined SQL stored in database

⸻

📌 Example (SQL Server)

CREATE PROCEDURE GetEmployees
AS
SELECT * FROM Employees;


⸻

📌 Call in EF Core

var data = db.Employees
             .FromSqlRaw("EXEC GetEmployees")
             .ToList();


⸻

📌 With Parameter

var data = db.Employees
             .FromSqlRaw("EXEC GetEmployeeById @id={0}", 1)
             .ToList();


⸻

⚡ Advantages
	•	Faster execution
	•	Secure
	•	Reusable

⸻

❌ Disadvantages
	•	Harder to maintain
	•	Less flexibility

⸻

🔹 6. When to Use What?

⸻

✅ Use Change Tracking
	•	When updating data

⸻

✅ Use No Tracking
	•	For read-only operations

⸻

✅ Use Transactions
	•	For multiple dependent operations

⸻

✅ Use Raw SQL
	•	Complex queries

⸻

✅ Use Stored Procedures
	•	High performance + reusable logic

⸻

🎯 FINAL SUMMARY
	•	Change Tracking → tracks entity changes
	•	AsNoTracking → improves read performance
	•	Transactions → ensures consistency
	•	Raw SQL → direct query execution
	•	Stored Procedures → reusable DB logic
