🔹 1. Why Performance Optimization?

🧠 Definition

👉 Performance optimization means:

Making database operations faster and efficient

⸻

📌 Why needed?
	•	Large data handling
	•	Multiple users (Web API)
	•	Reduce memory usage
	•	Faster response time

⸻

🔹 2. AsNoTracking() 🔥

⸻

🧠 Definition

👉 AsNoTracking() tells EF:

“Do NOT track this data”

⸻

📌 Example

var data = db.Employees
             .AsNoTracking()
             .ToList();


⸻

🧠 Internal Working

👉 Normally:
	•	EF stores entity in memory (tracking)

👉 With AsNoTracking:
	•	No tracking
	•	Direct read

⸻

✅ Advantages
	•	Faster queries
	•	Less memory usage
	•	Best for read-only

⸻

❌ Disadvantages
	•	Cannot update data directly

⸻

🎯 When to Use?

👉 Use when:
	•	Data is read-only
	•	No update required

⸻

🔹 3. Efficient Querying 🔥

⸻

🧠 Concept

👉 Fetch only required data

⸻

❌ Bad Practice

var data = db.Employees.ToList();

👉 Loads all columns ❌

⸻

✅ Good Practice (Projection)

var data = db.Employees
             .Select(e => new 
             {
                 e.Name,
                 e.Salary
             })
             .ToList();


⸻

🔥 Benefits
	•	Less data transfer
	•	Faster performance

⸻

⚡ Filtering Early

var data = db.Employees
             .Where(e => e.Salary > 50000)
             .ToList();

👉 Filter at DB level (not in memory)

⸻

🔹 4. Indexing Basics 🔥

⸻

🧠 Definition

👉 Index = Improves search speed in database

⸻

📌 Example

👉 Without index:
	•	Full table scan ❌

👉 With index:
	•	Direct search ✅

⸻

🔥 In EF Core

Using Fluent API

protected override void OnModelCreating(ModelBuilder modelBuilder)
{
    modelBuilder.Entity<Employee>()
        .HasIndex(e => e.Name);
}


⸻

📌 SQL Equivalent

CREATE INDEX IX_Employees_Name ON Employees(Name);


⸻

⚡ When to Use?
	•	Frequently searched columns
	•	WHERE condition
	•	JOIN columns

⸻

❌ Avoid
	•	Too many indexes → slow insert/update

⸻

🔹 5. Avoiding N+1 Problem 🔥🔥🔥

⸻

🧠 What is N+1 Problem?

👉 Multiple unnecessary queries

⸻

📌 Example (BAD)

var employees = db.Employees.ToList();

foreach (var emp in employees)
{
    Console.WriteLine(emp.Department.Name);
}


⸻

🧠 What happens?
	•	1 query → Employees
	•	N queries → Departments

👉 Total = N+1 queries ❌

⸻

🔥 Solution: Eager Loading

var employees = db.Employees
                  .Include(e => e.Department)
                  .ToList();


⸻

🧠 Result

👉 Only 1 query ✅

⸻

🔹 6. Other Optimization Tips

⸻

🔥 Use Async

await db.Employees.ToListAsync();

👉 Improves scalability

⸻

🔥 Limit Data

var data = db.Employees.Take(10).ToList();


⸻

🔥 Use Pagination

var data = db.Employees
             .Skip(10)
             .Take(10)
             .ToList();


⸻

Technique	Benefit
